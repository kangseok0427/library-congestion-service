# 협업

1. 공용 저장소를 fork하거나 쓰기 권한이 있으면 clone합니다.
2. 최신 develop에서 feature/ADE-xx-name 또는 fix/ADE-xx-name을 만듭니다.
3. 공통 규격 v1을 유지하고 테스트를 실행합니다.
4. 공용 develop 대상으로 PR을 제출합니다. PR 템플릿을 채웁니다.
5. 리뷰와 CI 확인 후 담당 관리자가 merge합니다.
6. 통합 검증된 develop만 main으로 PR을 제출합니다.

Public 저장소는 읽기/fork/PR이 가능하지만 누구나 직접 merge하는 설정은 아닙니다.
팀원의 GitHub ID를 확인한 소유자가 필요한 쓰기 권한을 부여합니다.
강제 push, 원본 Excel 및 실데이터 commit을 피하세요.
