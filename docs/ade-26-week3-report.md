## 2. 추가하면 좋을 기능

- **제안 (가): OUT_11을 일일 전체 OUT에서 복원.** `OUT_11 = 전체_OUT − (다른 시간 OUT 합)`.
  이유: 지금 (나) 규칙에서는 하루 12시간 중 10시간이 비어 추정 체류 인원 화면의 가치가 크게 떨어진다.
  복원하면 11시 이후도 계산할 수 있고, 값을 지어내지 않고 원본의 다른 칸에서 얻는 방식이라 근거가 분명하다.
  전제는 `전체_OUT`이 시간대 칸을 더한 값이 아니라 장비가 따로 센 정확한 값이어야 한다는 것이다.
  실제 Excel에서 날마다 `전체_OUT`과 `OUT_11을 IN_11로 둔 시간대 OUT 합`을 비교해, 매일 같으면 쓸 수 없고
  다르면 복원을 검토한다. 강민재님께 확인하고 싶다.
- **실제 Excel로 "자료 부족" 비율을 재는 확인 단계.** 합성 데이터 테스트는 규칙이 맞게 동작하는지만 보여 준다.
  ADE-39 초안에 따르면 OUT이 하루 약 40명 더 많이 세어져 음수가 생길 수 있어, 실제 비율을 봐야 배포를 판단할 수 있다.

## 3. 제거·축소하면 좋을 기능

- **축소: 추정 체류 인원 "숫자" 표시.** ADE-39 초안은 이 값이 음수까지 나오는 추정치라 숫자 대신 색만 보여 주자고 한다.
  ADE-41 명세대로 지금은 숫자를 보여 주게 했지만, 실제 오차가 크면 숫자를 숨기고 색과 단계만 남기는 편이
  이용자 오해를 줄인다. 프론트에서 숫자 칸만 가리면 되는 작은 변경이라 10/1 토론에서 정했으면 한다.
- **유지 검토: 기존 입장량 기준 표시.** (나) 상태로 배포하면 11시 이후 정보가 사라진다. (가)가 성립하지 않으면
  11시 이후는 기존 입장량 기준 표시를 남기는 방안도 함께 검토할 만하다.
- **축소: 미래 날짜의 "실제 집계" 카드.** 오늘을 뺀 7개 날짜에서는 항상 "집계 전" 또는 "휴관일"만 나온다.

## 4. 품질과 개발 효율

- **백엔드 변경은 팀 저장소 PR로.** ADE-40이 별도 저장소에서 만들어져 날짜 조회·운영 달력·KST가 빠졌고,
  완료 알림 뒤에도 화면에 연결되지 않았다. 팀 저장소였다면 기존 테스트가 이 차이를 바로 잡았을 것이다.
- **실제 데이터 전처리 규칙을 테스트 입력에 반영.** ADE-40 원본 테스트는 OUT_11이 정상인 데이터만 써서
  "매일 11시 이후 전부 비는" 결과를 드러내지 못했다. ETL 규칙(OUT_11 null)을 넣은 합성 데이터를 기본 테스트 입력으로 쓰면 좋겠다.
- **테스트가 실제로 결함을 잡는지 확인.** 이번에 핵심 규칙을 일부러 깨 보니 처음엔 한 경우를 못 잡아 테스트를 보강했다.

- ADE-39 초안(숫자 대신 색만)과 ADE-41 명세(숫자 표시)가 서로 다른 방향이다. 이슈를 나눌 때 표시 방식을 먼저 맞췄으면 좋았겠다.
- ADE-40 이슈 본문이 "OUT_11 처리 규칙을 자료 담당과 확인"하라고 했는데 이 확인이 빠진 채 완료 알림이 왔다.
  완료 전에 자료·계산 담당이 함께 확인하는 단계가 필요하다.
- Linear 상태와 실제가 다른 경우가 있었다(ADE-38 Done/댓글 In Progress, ADE-40 Todo/댓글 완료).
