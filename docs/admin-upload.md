# 관리자 웹 Excel 업로드 운영 전환

2026-10-03 기준: 운영 방향과 API v2 계약은 확정됐지만 새 화면·세션 API의 통합 및
실제 운영 반영은 아직 확인하지 않았습니다. 운영 서버에 새 기능이 있다고 안내하지 않습니다.

## 통합 완료 후 사용할 절차

1. ADE-50이 검증한 관리자 웹 주소에서 계정으로 로그인합니다. 주소·계정은 운영 담당자가 제공합니다.
2. `.xlsx`를 선택합니다. 공통 계약의 파일 크기 제한은 10 MB입니다.
3. 서버의 공용 Excel 전처리 검증 결과를 확인합니다. 오류이면 게시하지 않고 기존 정상본을 유지합니다.
4. 성공하면 활성 버전, 생성 시각, 원본 파일명, 레코드 수와 경고를 확인합니다.
5. 버전 목록에는 최신 정상 JSON 4개가 남습니다. 데이터 이상이면 보관 중인 이전 버전을 선택해 롤백합니다.
6. 실제 이용자 API와 웹 새로고침에서 통계·예측이 변경됐는지 확인합니다.

이 순서는 구현 후 검증할 운영 절차입니다. 현 시점에 사용 가능한 화면으로설명하지 않습니다.

## 담당별 연결

- ADE-44: Excel 검증 기준·정상/실패 fixture·오류 코드. 아직 계약 파일이 없으므로 기존 전처리 기준을 임의 변경하지 않습니다.
- ADE-45: 서버 공용 전처리 재사용, 원자 게시, 4세대 보관, 잠금, 재시작 복구, 롤백.
- ADE-46: 세션과 `POST /api/v1/admin/uploads`, `GET /api/v1/admin/versions`,
  `POST /api/v1/admin/versions/{version_id}/rollback`. [API v2 계약](../contracts/README.md)을 사용합니다.
- ADE-47: 관리자 웹 화면. 별도 설치 프로그램 없이 브라우저에서 사용합니다.
- ADE-50: 실제 Excel, 인증·크기 제한, 실패 보존, 동시 요청, 롤백 후 API·화면과 운영 배포 검증.

## 서버와 자료 보존

운영 데이터는 `LIBRARY_RECORDS`가 지정하는 Git 밖 영구 경로에 둡니다.
ADE-45의 저장 구조가 통합되면 활성 JSON과 버전 저장소를 함께 백업·복구해야 합니다.
새 저장소의 구체적 복구 명령은 ADE-45 인수인계 문서를 기준으로 운영 담당자가 검증합니다.
초기 합성 샘플을 실제 운영 이력과 병합하지 않는 최초 전환 절차도 ADE-50에서 확인합니다.

공용 `library_etl/`, openpyxl, FastAPI, uvicorn은 계속 사용합니다.
현재 서버 인증 코드·설정은 호환을 위해 보존합니다. 기존 인증 방식의 폐기와 비밀값
회수는 운영 검증 후 결정하며 새 관리자 화면에는 비밀값 입력란을 만들지 않습니다.

## 제거와 과거 이력

ADE-48에서 설치형 패키지, 전용 의존성 파일, 실행파일 빌드 진입점·스크립트와 전용 테스트를 제거했습니다.
서버 테스트는 유지하고 클라이언트에 종속된 두 테스트만 제거했습니다.
keyring과 PyInstaller의 사용처는 제거된 설치형 패키지와 빌드 코드에만 있었습니다.
기존 공용 requirements와 잠금 파일에 해당 패키지가 없으므로 수정하지 않았습니다.
`docs/windows-uploader.md`는 과거 링크를 위한 변경 이력만 남겼습니다.
Week 3 보고서와 Git 이력은 당시 상태를 설명하는 자료로 보존합니다.
