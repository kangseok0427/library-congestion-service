# T04 혼잡도 판정 기준 · T05 이용자 웹

## T04 혼잡도 판정 기준

구현 파일은 `backend/congestion.py`입니다.

- `midrank_score(value, distribution)`: 과거 동일 시간대 방문량 분포에서 백분위 점수와 단계를 계산합니다.
- `classify(score)`: 35 이하는 `quiet`, 70 이하는 `normal`, 70 초과는 `busy`로 분류합니다.
- `label(level)`과 `description(level)`: 이용자 표시용 한글 단계와 설명을 반환합니다.
- `criteria_info()`: 판정 기준, 단계명, 안내 문구를 API 메타데이터로 사용할 수 있게 반환합니다.
- 기준값은 `THRESHOLDS`, 표시명은 `LABELS`에서 한 번에 관리합니다.
- 좌석 점유율이나 현재 체류인원을 계산하지 않습니다.
- `backend/prediction.py`의 `percentile()`은 `midrank_score()`를 호출하므로 판정 로직이 한 파일에 모입니다.

검증은 `tests/test_congestion.py`에서 빈 분포, 경계값, 동일값 분포, 단계명과 기준 정보를 확인합니다.

## T05 이용자 웹

구현 파일은 `frontend/`에 있습니다.

- `api.js`: API 주소와 `meta`, `today`, `stats` 요청 및 공통 오류 처리를 담당합니다.
- `app.js`: 조회 상태와 화면 렌더링을 담당하며 데이터는 `api.js`를 통해서만 받습니다.
- `index.html`: 날짜, 예상 혼잡 단계, 추천 시간, 시간대별 예상 방문량, 실제 집계, 갱신 시각을 표시합니다.
- `style.css`: 390px 모바일 화면을 기준으로 구성하고 600px 이상에서는 표를 기본으로 펼칩니다.

표시 상태는 다음과 같습니다.

- 합성 샘플이면 경고 배너 표시
- 예측 자료가 없으면 `자료 부족` 표시
- 실제 집계가 없으면 해당 날짜 자료 없음 표시
- 네트워크·서버 오류가 발생하면 이전 숫자를 지우고 오류 메시지 표시
- 예상 방문량이며 현재 체류인원이 아니라는 안내 상시 표시

API 응답 형식이 유지되면 배포 주소 변경은 `api.js`의 `BASE_URL`만 수정합니다.

## 검증

```sh
python -m playwright install chromium

```
